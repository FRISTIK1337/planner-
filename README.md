# fristik.planner — GitHub Pages static build

Проект не требует Node.js, npm, сборщика или сервера. Все иллюстрации хранятся локально в `assets/images/`; внешние CDN для картинок не используются.

## Структура

```text
index.html
style.css
app.js
assets/
  images/
    cases/
    characters/
    embedded/
    forms/
    stands/
```

## Публикация на GitHub Pages

1. Распакуй этот архив на компьютере.
2. Открой **внутреннюю папку проекта** и выдели `index.html`, `style.css`, `app.js`, `README.md` и всю папку `assets`.
3. Загрузи их в корень репозитория. В GitHub корень должен сразу содержать `index.html` и `assets/` — не оставляй их внутри дополнительной вложенной папки.
4. Перейди в `Settings → Pages → Deploy from a branch`, выбери `main` и `/ (root)`.
5. После публикации открой адрес Pages и обнови страницу с полной перезагрузкой: `Ctrl + Shift + R`.

## Если изображения не появились

- Проверь, что папка `assets` видна рядом с `index.html` в корне репозитория.
- Открой в браузере напрямую адрес вида `https://USERNAME.github.io/REPOSITORY/assets/images/cases/basic.jpg`. Если получаешь 404, папка `assets` загружена не в корень или не полностью.
- Убедись, что регистр букв в названиях папок и файлов совпадает: GitHub Pages чувствителен к регистру.
- После загрузки всех файлов подожди завершения deployment и выполни `Ctrl + Shift + R`.

Все растровые изображения конвертированы в JPEG (логотип с прозрачностью — PNG), чтобы избежать проблем с поддержкой WebP на сторонних хостингах. Пути используют `./` и `<base href="./">`, поэтому корректно работают на проектном URL GitHub Pages.

## Данные

Прогресс хранится в `localStorage` браузера. Перед заменой версии экспортируй резервную копию через кнопку «Экспорт».
